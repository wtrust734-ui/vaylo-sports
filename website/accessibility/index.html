Accessibility

What this site does, and what has not been checked

This statement covers the website you are reading. It says what is built in, and then it says plainly what has not been tested, because the second list is the one that is usually left out.

No conformance level is claimed on this page. No independent review of this site has been carried out. Putting “WCAG 2.2 AA” here without one would be a claim you have no way to check, and the person most likely to catch it would be the one who needs it to be true.

Built in

What this site does

Each of these is a property of the pages as generated, not an intention. The last two are enforced when the site is built.

  • A skip link is the first focusable element on every page. It moves off the canvas rather than being hidden with opacity, so it can never be an accidental click target for a mouse user and it still takes focus.
  • The page structure is real landmarks — header, navigation, main and footer — so a screen reader can jump between regions, with exactly one top-level heading per page.
  • The current page is marked in the markup, not only in colour, with aria-current, so it is announced rather than merely implied.
  • Every focusable control has a visible focus ring, and the stylesheet never removes or zeroes an outline.
  • The mobile menu uses the hidden attribute, so it leaves the tab order when it is closed instead of trapping a keyboard user inside something they cannot see. Its button reports its state with aria-expanded.
  • Motion is optional. Every animation and transition on the site is switched off when the device asks for reduced motion, including the one whose starting state is invisible.
  • Both a light and a dark theme, following the system setting, with the colour scheme declared so form controls, scrollbars and the browser's own interface follow the page rather than staying light behind it.
  • Tap targets. Navigation items are at least 44 pixels tall and buttons and inputs at least 48 pixels, which is what stops a link being missed on a phone.
  • Forms have real labels, hints wired up with aria-describedby, invalid fields marked for assistive technology, and errors announced in a live region rather than only shown in red. The anti-spam trap field is hidden from the accessibility tree, not just visually, so nobody is asked about a field that does not exist for them.
  • Tables use real header cells and scroll inside their own container, so a wide table does not make the whole page scroll sideways on a phone.
  • Text is real text. The only images on the site are the brand mark and the social card, and the mark is marked decorative wherever the wordmark beside it already carries the name.
  • Two of these are enforced by the build. The site fails to generate if the stylesheet removes or hides the focus outline, and it fails if any component is emitted with no styling rule at all — which is the mechanism, rather than a promise, behind the first and the last items above.

Honestly

What we have not done

These are gaps, not caveats, and they are the reason no conformance level appears at the top of this page.

  • No independent accessibility audit has been carried out. Nothing here has been reviewed by a specialist, and no third party has tested the site with assistive technology.
  • No full screen-reader pass across every page. The markup is written to be read correctly and the structure is enforced by the build, but that is not the same as having listened to all 40-odd pages with every major screen reader, and we are not going to describe the site as accessible without qualification until that has happened.
  • The Android app is a different surface. Its accessibility depends on the platform's own features and on the app's own markup, and none of that is reviewed by this statement. Do not read this page as describing the app.
  • Automated checks are not a substitute for a person. The build checks described above catch a missing style rule or a removed focus ring. They cannot tell whether the result is actually usable.

Tell us

If something here does not work for you

A barrier you hit is a defect, whether or not it appears on a list like the one above, and it is treated as one.

Write to us through the contact page and describe what you were trying to do and what happened, including the page and the browser or assistive technology if you know it. If a barrier stopped you doing something on this site, say so in those words — it goes to a person, and it is not a support ticket about your account.

If the response is not good enough, the complaints procedure sets out how to ask for it to be reviewed and how to take it further if you are still not satisfied.
