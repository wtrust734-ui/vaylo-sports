## 1. UX issues found (live walk + crawl)

1. **Cookie notice overlaps content on the Market** — the fixed-bottom cookie
   card covers the Starter pack card (verified in screenshot; its `7rem`-lift
   token is on other surfaces but the Market's pack cards scroll under it with
   no offset). Cosmetic but reads as broken on first store visit.
2. **Market section-nav clips its last icon** — the horizontal section row
   (`Credit Packs · Unlocks · Coins · Subscriptions · Lifetime`) cuts the last
   pill's icon at 320px with no scroll affordance. One more section would be
   worse.
3. **Empty-state dead ends** — Home shows "No training plan yet" with a
   working CTA (good), but Perform's "Trend needs 2 saves" and VPR "log 6
   metrics across 4 areas" leave the athlete on the same screen they already
   read; the nudges don't deep-link to the logging form (VPR has it inline —
   good — but the copy above it repeats three times).
4. **Terms reacceptance banner is heavy** — 320px shows the ToS card before
   every page's content and requires scrolling past it each crawl; consider a
   compact pill with an expand affordance. (Copy itself is excellent and
   honest.)
5. **VPR form pre-announces price-free friction** — the "Save & Recalculate"
   button is disabled until fields are filled, with no helper text on *why* it
   is disabled; a reason string would cut abandonment.
6. Everything else checked clean: 46/46 routes render, no horizontal overflow,
   no notch-covered content, no fixed-bottom element under the tab bar.

## 2. Feature verification (features work)

- **Sign-in session persisted; tabs keep-alive works** (state stays across tab

## 3. Code quality / efficiency findings

1. **89 call sites use `select("*")` against Supabase** — the largest
   systemic inefficiency in the client. Each pulls every column (including
   large JSON columns like `plan_data`) over the wire when screens usually need
   3–6 columns. On a mobile WebView this shows up directly as cold-start and
   tab-switch latency. Highest-value single refactor if you want more speed
   later. (`src/pages/Training.tsx`, `src/pages/Goals.tsx`, `Market.tsx` are
   the heaviest.)
2. **`notificationTriggers.ts` runs a serial `await`-in-loop for the morning
   briefings** (`for (const day of nextMorningDates(now))`) — 7 sequential
   Supabase writes on a cold open where a `Promise.allSettled` batch would
   collapse them into one round trip each, not seven. Same shape exists in the
   challenge-deadline loop for multi-challenge athletes.
3. **Mixed static+dynamic import of `supabase/client.ts`** — `starterOffer.ts`
   dynamically imports the client while 100+ files import it statically, so the
   dynamic-import code-split is defeated and the module stays in the main
   chunk. Cosmetic bundle-wise, but the warning fires every build (visible in
   our logs).
4. **`chart.tsx` uses `dangerouslySetInnerHTML` for chart theme CSS** — safe
   today (values are developer-supplied theme colors, not user input), but a
   latent XSS sink if chart colors ever come from server data. Worth a comment
   or a CSP-safe rewrite when touched next.
5. **react-refresh warnings (17)** — files exporting both components and
   constants; minor dev-experience issue, no runtime cost.
6. **react-hooks/exhaustive-deps warnings (29+)** — several in the market /
   dashboard files. Not bugs today (they're caught by the existing test
   contract), but the compiler is flagging genuine "could stall/stale-render"
   risk. Recommended: fix the five in `components/market/*` first.
7. No `console.log`/`debugger` leaks found in the shipped components and
   configs (the APK scan also confirms 0 JWTs / 0 source maps in the bundle).

## 4. Security audit (found-only, NOT fixed)

### 4a. Dependency vulnerabilities (`npm audit`)

Production tree — 4 advisories, none exploitable from this app's code paths:

| Package | Severity | Issue | Why it matters (or doesn't) here |
|---|---|---|---|
| `braces` (`tailwind` dep chain) | high | Stack-exhaustion DoS via deeply nested glob patterns | Build tooling only; not shipped |
| `source-map-js` | high | Event-loop DoS via crafted sourcemap | Build-time only |
| `postcss-selector-parser` | moderate | Quadratic-complexity CPU exhaustion | Build-time only |
| `react-router` 6.x | moderate | CVE-2025-68470 bypass: open redirect via `\` in `<Link>`/`useNavigate`, plus SSR `deserializeErrors()` constructor injection | **Real risk class**: the app uses `useNavigate` everywhere, but navigation targets are all in-app constants — no user-controlled redirect strings found. Upgrade to 7.x is a breaking change; schedule it. |

Dev tree additionally: **`tinypool` critical** (RCE-grade prototype pollution in
worker options) via `vitest@2` — CI/test-only, not shipped, but upgrade when
convenient. Plus `esbuild`/`@vitest/mocker`/`uuid` moderates, same class.

### 4b. Secrets and keys

- `secret-scan`: **PASS** (11 rules, 1108 files, 0 findings).
- The frontend ships `sb_publishable_…` and the Supabase URL inline — **by
  design** (publishable key, not a secret). `.env.example` documents the
  distinction, APK scan confirms **no service-role or JWT-shaped secrets** in
  the bundle.

### 4c. Edge-function / auth posture

- `security-check`: **31/31 PASS** — RLS isolation verified functionally
  (can't send-as another athlete, can't rewrite friend-gated messages, can't
  READ other users' data).
- **`guard.ts` sends `Access-Control-Allow-Origin: *` on all edge functions.**
  Combined with Bearer-token auth this is not an immediate credential leak
  (requests still require the user's JWT), but it lets any malicious origin
  invoke functions with a stolen token from a browser; the tight REMAINING
  hardening is an origin allowlist pass per function. NOT changed, per scope.
- **`ai_call_allowed` fails OPEN** on limiter DB outage — right availability
  call, but it means budget throttling is not a hard security boundary under
  outage (credits are the hard bound; noted as accepted-risk design).
- **`auth:posture`: 3 AT RISK** — requires one-time Supabase **Dashboard**
  changes (not code):
  1. Minimum password length < 8 accepted (6-char password signs in fine) —
     raise the min-length policy.
  2. Email confirmation is NOT required — signups get a session unconfirmed,
     enabling free-trial farming via disposable emails.
  3. No rate limit on wrong-password attempts — 12 failures, no 429. Set
     token+password brute-force rate limits in Authentication settings.
- Note: this run left two probe accounts behind
  (`authposture.…@example.com`) — delete in Dashboard → Authentication →
  Users, or re-run with `--cleanup` + service-role key.

### 4d. CSP / browser surfaces

- `dangerouslySetInnerHTML` exists only in `chart.tsx` (dev-owned theme colors)
  — safe now, flagged above.
- No `eval`, no `new Function`, no `postMessage` handlers, no `target=_blank`
  without `rel="noopener"` patterns detected in the client tree.

## What was NOT tested (and why)

- **Real payment flow** — needs a Play purchase connection; not exercised in
  the walk (`purchaseItems` is wired to server-side verification; the
  free-grant path is test-flagged).
- **Health Connect native sync** — requires a device with the sensor; bundle
 umidity permissions/contract covered by unit tests instead.
- **Live push (FCM)** — Firebase is unconfigured by design (`vaylo_fcm.xml`
  placeholders); the app degrades to local notifications, which do work.
