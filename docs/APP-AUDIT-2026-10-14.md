### P1 — referral RPC grants referrer bonus at redemption

The live project has `redeem_referral` from the earlier September migration, which immediately awards both referee and referrer, marking the referral `granted`. The new paid-purchase gate migration replaces it with pending attribution and referee-only welcome credits; it is currently unapplied. The local `process-purchase` settlement further checks that the transaction reference exactly matches the selected purchase row. These are source changes only until migration application and edge function deployment.

Evidence: [qualification migration](../supabase/migrations/20261014220000_referral_qualification_gate.sql#L31-L94), [process-purchase](../supabase/functions/process-purchase/index.ts#L655-L670).

### P1 — referral qualification verifies a paid purchase, not the purchaser's identity

The transaction reference is used only for idempotency/audit and hashed before qualification storage. It is not treated as a payment-method fingerprint. No payment identity is collected. The referral offer now accurately claims purchase confirmation only; any future shared-payment method fraud signal needs a separately reviewed provider-supported signal.

Evidence: [process-purchase/index.ts](../supabase/functions/process-purchase/index.ts#L650-L660); [qualification migration](../supabase/migrations/20261014220000_referral_qualification_gate.sql#L25-L29).

### P1 — purchase-row linkage and basket idempotency

Purchase rows are now linked by their exact in-memory basket item rather than a product-ID search. A store transaction reference is attached only to the first positive-price row to satisfy the global unique index. The referral settles against that exact paid row; free and credit-priced baskets do not qualify. Each row write failure aborts before grants continue. Multi-row purchase grants are still not one database transaction, so partial basket recovery remains a separate risk.

Evidence: [process-purchase/index.ts](../supabase/functions/process-purchase/index.ts#L461-L490), [global index migration](../supabase/migrations/20260930131434_security_integrity_hardening.sql#L57-L60).

### P1 — referral qualification reads and errors

The app now reads an aggregate count through an own-user-only RPC instead of querying transaction rows. Loading and failure are separate from a real zero count; referral code and referral-list request errors also surface to the athlete. The migration must be applied to the connected Supabase project before the new aggregate RPC can work.

Evidence: [Referrals.tsx](../src/pages/Referrals.tsx#L84-L100); [qualification migration](../supabase/migrations/20261014220000_referral_qualification_gate.sql#L63-L88).
